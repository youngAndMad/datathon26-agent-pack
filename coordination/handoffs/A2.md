## Endpoints (all behind the X-API-Key ingress gate; 401 sent before any body read; standard error body)
| Route | Result |
|---|---|
| `POST /api/v1/jobs/{job_id}/events/{event_id}/review` | 201 `EventReview`. 404 unknown job / event not in report.json (and not `missed`); 410 expired; 409 `job_not_done` (processing/failed); 413 body > 16 KiB (Content-Length or streamed); 422 `invalid_request` (malformed/extra fields/negative time); 422 `invalid_review` (decision `missed` ⇔ event_id `missed`; `missed` without timecode; timecode > source duration, or any timecode when report.source is unknown) |
| `GET /api/v1/jobs/{job_id}/reviews` | 200 `list[EventReview]` chronological (append order); `[]` for non-done |
| `GET /api/v1/jobs?limit=50&status=processing\|done\|failed` | 200 `JobListResponse`, newest first by trusted received_at; limit 1..200 (else 422); expired jobs not listed; reviewed_event_count = distinct event_ids ≠ `missed` |
| `GET /api/v1/jobs/{job_id}/export` | 200 `ExportBundle`, `Content-Disposition: attachment; filename="cashwatch-<job_id>.json"`; `original_jury_result` = parsed stored jury.json; 409 if not done |
| `GET /api/v1/jobs/{job_id}/report` | now includes rule_coverage, quality_notes_ru, review_required, reviews (old report.json without these fields → defaults) |

```bash
K='<jury-api-key>'; B=http://127.0.0.1:8000
curl -s -H "X-API-Key: $K" -H 'Content-Type: application/json' -d '{"decision":"confirmed","comment":"ok","reviewer":"r1"}' $B/api/v1/jobs/<job_id>/events/<event_id>/review
curl -s -H "X-API-Key: $K" -H 'Content-Type: application/json' -d '{"decision":"missed","corrected_timecode_sec":42.5,"corrected_type":"..."}' $B/api/v1/jobs/<job_id>/events/missed/review
curl -s -H "X-API-Key: $K" $B/api/v1/jobs/<job_id>/reviews
curl -s -H "X-API-Key: $K" "$B/api/v1/jobs?limit=20&status=done"
curl -s -OJ -H "X-API-Key: $K" $B/api/v1/jobs/<job_id>/export
```

## Limitations / assumptions
- Reviews are not tied to a reviewer identity beyond the free-text `reviewer` field (single shared jury key).
- Timecode validation needs `report.source.duration_sec`; when absent every corrected_timecode is rejected (422).
- An accepted event literally named `missed` would be indistinguishable from the missed-event slot (pipeline ids are e<N>).
- `mode` for processing/failed list rows = API `settings.mode` (same as /report); done rows use report.json mode.
- `contracts/openapi.json` (orchestrator-owned) does not yet list the new UI routes.
- `GET /api/v1/jobs/` (trailing slash) redirects to the list (Starlette default).
