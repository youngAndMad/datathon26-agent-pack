# Windows: экспериментальная модель 2B

Цель — снизить память локального анализа и измерить скорость на ноутбуке.
Модель: [Qwen/Qwen3-VL-2B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct),
ревизия `89644892e4d85e24eaac8bacfd4f463576704203`, лицензия Apache-2.0.
Исходные веса BF16 занимают примерно 4,3 ГБ на диске. Потребление RAM после
INT8-преобразования и скорость полного анализа ещё не измерены.

## Подготовка, запуск и контрольный анализ

Из обычного PowerShell с доступом к интернету:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Users\berik\Desktop\project\deploy\start_windows_2b.ps1" -Prepare -Smoke
```

Скрипт использует существующее `.venv-windows`, ничего не устанавливает и не
меняет версии. Скачивает только явно перечисленные файлы закреплённой ревизии,
проверяет размер и опубликованные SHA256/Git blob hashes. Затем создаёт отдельный
игнорируемый Git манифест `models/manifest.windows-2b.json`, собирает интерфейс,
запускает модель локально и проверяет искусственный секундный MOV через API.
Если скачивание или проверка не прошли, сервер не запускается. Частичное скачивание
можно продолжить повторной командой. Системные proxy-настройки не изменяются.

Результаты проверки: `data/windows-local/2b-smoke-summary.json` и
`data/windows-local/2b-smoke-memory.json`. Второй файл измеряет доступную RAM всей
системы раз в 0,5 секунды во время анализа; это не изолированный расход модели
и не пик при загрузке весов. Ошибка анализа возвращает ненулевой exit code.

После подготовки интернет для запуска не нужен:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File deploy\start_windows_2b.ps1 -Smoke
```

Перед сменой модели/повторным запуском:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File deploy\stop.ps1 -WindowsLocalTest
```

Один worker, одна активная проверка, очередь отключена. Квантизация выполняется
по слоям, самая большая матрица преобразуется первой; нет полной копии FP32.
Веса Linear хранятся INT8, embedding — BF16 с FP32-выходом. Видеодекодирование
уже потоковое; общий реестр банковских правил не включается. Лимит наблюдения
для этого CPU-режима 180 секунд, общий дедлайн задания 270 секунд.

Это тестовый режим с настоящей моделью и синтетическим правилом TEST01.
Даже успешный искусственный ролик не подтверждает качество банковских проверок.
macOS-скрипты, общий `models/manifest.json`, `configs`, Python и зависимости
сохранены. Обычный 4B-запуск также сохранён.

## Статус проверки 2026-10-17

Пользователь скачал и запустил 2B. Офлайн-проверка `scripts/windows_model_2b.py
--verify-only` подтвердила целостность 11 файлов. Endpoint готовности подтвердил
настоящий Transformers backend с 2B в тестовом режиме. Последняя проверка
завершилась таймаутом `observe-repair` (30 секунд).

В локальном master исправлена обработка необязательного описания: некорректный
JSON нейтрального описания не тратит бюджет на повторную генерацию, когда далее
выполняется обязательная проверка признаков. Ошибки самой генерации не скрываются.
Новая версия пока не проверена на реальной модели: Windows отказала coding-agent
в доступе к остановке запущенных пользователем процессов. Требуется выполнить
команды остановки и запуска с `-Smoke` выше из обычного PowerShell.
Успешное завершение анализа, время и пиковая память новой версии не подтверждены.

## Следующий этап: данные и дообучение

Обучение не запускается до успешного базового анализа. Сначала сравнить меньшую
модель с базовой на отложенных роликах: пропуски, ложные тревоги, таймкоды,
пиковая память и время. Если качество недостаточно, подготовить локальную
разметку наблюдаемых действий и затем отдельное окружение для LoRA/QLoRA.
Текущий Windows dynamic INT8-loader предназначен только для инференса.

Разметка должна содержать: идентификатор исходного видео, границы события,
наблюдаемые факты, допустимый тип события, корректные ситуации и случаи
неопределённости. Не подменять наблюдения юридическими догадками. Отделить train,
validation и test по исходным роликам/сценам, чтобы соседние кадры не попадали
по разные стороны. Ролики жюри не использовать для обучения. Приватную разметку
держать в существующих ignored-папках; в cloud coding-agent её не передавать.
Человек или локальный инструмент должен подготовить и проверить эти данные.
Не генерировать обучающие ответы из неподтверждённых предсказаний самой модели.
