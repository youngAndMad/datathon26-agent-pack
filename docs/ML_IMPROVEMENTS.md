# Доработки анализа и план проверки

## Реализовано

1. Подтверждение `yes`/`no` требует явных ссылок на существующие кадры. Ответ без
   ссылок больше не превращается в доказательство на первом кадре окна. Один
   ограниченный повторный запрос получает изображения. После него сохраняются
   только корректные строки; неизвестные и противоречивые оценки остаются unknown.
   Предварительные сигналы используются только для поиска кандидатов, не как итоговые доказательства.
2. Принятое событие привязано к подтверждённому кадру решающего признака. Кандидат
   с другим кадром нельзя пропустить только потому, что он попал в интервал ранее
   принятого события.
3. Дубликаты объединяются по правилу, источнику, пересечению событий или общему
   решающему доказательству, с учётом восстановления исходного состояния. Простая
   близость в 10 секунд и общий контекст не объединяют разные действия.
4. CW11: недостаточно прихода человека; проверяются фактическое обслуживание,
   связь с предыдущей партией денег и видимое помещение этой партии в хранилище.
   Невидимая уборка не считается доказательством оставленных денег.
5. CW12: проверяются действие кассира и связь с тем же предметом. Присутствие
   постороннего человека, уход кассира и цвет сумки не устанавливают личную собственность.
6. CW14 уточнён для эксперимента: вставание не равно уходу; нужны передача и
   продолжающийся пересчёт той же партии после ухода. Правило осталось отключённым.
7. Опциональная плотная выборка вокруг предварительного якоря: до ±2 секунд,
   запрос кадров с шагом до 0,25 секунды. Общий контекст сохраняется, количество
   изображений модели остаётся ограниченным профилем. На 4 ГБ модель видит
   подвыборку, а не все 17 кадров: это не гарантия точности таймкода 0,25 секунды.
8. Опциональные крупные планы стола берутся из повторно декодированных исходных
   кадров, а не увеличенных миниатюр. Сохраняются исходные PTS, источник и общий
   вид. Кропы занимают места внутри существующего лимита изображений. Итоговые
   доказательства рендерятся из исходного видео, а не из кропа.
9. Отчёты оценки дополнены хешами парсера, движка правил, планировщика и кода кропов.

Общие конфиги и зависимости не менялись. Windows-профиль — отдельное расширение.
CW11/CW12 сохранили существующее разрешение владельца, но номера версий увеличены,
старые validation_counts помечены как исторические. Это не новая эмпирическая валидация.

## Включение крупного плана

Кроп по умолчанию отключён: координаты стола зависят от камеры. В экспериментальной
копии профиля задайте `sampling.desk_roi` с `enabled: true`, `rule_ids` и `bounds`.
`bounds` — четыре числа `[x0,y0,x1,y1]` в диапазоне 0–1 относительно изображения
после коррекции поворота. Настраивать их нужно локально для данного ракурса.
Без калибровки не переносите эту область на новую камеру. По умолчанию кроп
применим только к CW02/CW11/CW14. Он не включает отключённые правила.

## Проверено

- Синтетические тесты парсинга, условий правил, объединения, точных кадров,
  сохранения контекста, исходных PTS и ограничения размера пакета.
- Реальная локальная Qwen3-VL-2B CUDA NF4, RTX 3050 Laptop 4 ГБ: 8 синтетических
  кадров 384 px, наблюдение 42,469 с, подтверждение 7,875 с, по одному запуску.
  Это проверка выполнения, не банковской точности и не полной задержки HTTP API.
- ROI выключен в этом замере; его корректность проверена синтетическими тестами,
  реальная модель с калиброванной областью пока не оценивалась.

## Что ещё требует отдельного эксперимента

- Сравнить новую конфигурацию с предыдущей на одном наборе, учитывая ошибки,
  пропуски и неопределённость. Рост accuracy пока не заявлен. Различия моделей,
  профилей и состава данных мешают напрямую сравнивать Windows и Mac.
- Для ухода кассира при обслуживании уже существует отключённый CW01. Проверять
  его отдельно через режим кандидатов вместо дублирования CW10. Не включать
  общий вариант CW10, объединяющий разные ситуации, без подтверждённого основания.
- CW14 оценить отдельно, не переводить автоматически в production.
- Для CW12 остаётся вопрос визуальной проверяемости нормативных исключений для
  разрешённых предметов; конкретные исключения нельзя считать отсутствующими по умолчанию.
- Qwen 8B оценивать на подходящей машине тиммейта, фиксируя квантование, память,
  скорость и неизменные данные. Здесь такой замер не проводился.
- Новые разрешённые съёмки с другого ракурса необходимы для независимой оценки.
  На текущем наборе настройки уже выполнялись, поэтому это development-оценка.
- Публичный API и очередь нужно проверить отдельно на синтетических загрузках;
  данный набор изменений не публикует сервис и не передаёт видеоданные во внешние системы.

## Запуск оценки

После остановки сервиса, без параллельной загрузки модели:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File deploy\evaluate_windows_cuda.ps1 -Manifest evaluation\manifest\private\local-cuda-full\manifest.json -ExpectedClips 40 -RunName cuda-grounded-v2 -Profile deploy\runtime-profile.windows-cuda-4gb.json
```

Повторно используйте другое имя запуска. Подробные результаты остаются локально
в игнорируемой папке `data/dev_eval/`. Этот манифест оценивает классификацию,
но не точность таймкодов: эталонные таймкоды в него не импортированы.
